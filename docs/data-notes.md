# 数据说明与校准方法

> 更新：2026-09-18 ｜ 状态：v1 数据冻结，可用于网页开发

## 1. 时间公式（已对照 ComfyUI 0.34.0 源码验证）

源码依据：`comfy/ldm/minimax/model.py`（hidden 5376 / 50 层 DiT / attention 56×128 / ffn 14336 /
patch 1×2×2 / 时间压缩 4 / 音频 40 token/s）。

```
S（token 数）   = ceil(W/32)·ceil(H/32)·((frames−1)//4+1) + 40·round(frames/24) + 400
FLOPs/步        = 38.5e9·S + 1.434e6·S²
计算时间 s/it   = FLOPs/步 ÷ (k_attn × 显存带宽 GB/s × 1e12) × 精度修正
单步耗时        = max(计算时间, 非驻留权重流式时间) + 固定开销
生成总时间      = 加载 + TE 编码 + 步数 × 单步 + VAE 解码
```

- 线性项 = 2 × 20B 激活参数（33.1B 减去约 13B 被折叠为查表的 adaLN 分支）。
- 二次项 = 50 层全注意力；在 >3 万 token 后不可忽略（15s 视频慢于 3 倍线性的原因）。
- 30s 长视频实测显存峰值几乎与 5s 相同（14.2 vs 14.4 GiB）→ **token 只影响时间，不影响显存峰值**。

### 2.1 外部独立验证：5070 Ti 32 格矩阵（`scripts/verify-desktop4070.ts`）

用社区公开的 RTX 5070 Ti + 64GB DDR5 实测矩阵（Kitchen 注意力 + larryv4 8 步，
0.3–0.98MP × 5/8/10/15s 共 32 格，连续跑 165 条）逐格对比：

- **平均绝对误差 7.7%**（32 格）；除 1 格测量噪声外全部在 ±15% 内；
- 复现了两个此前模型缺失的规律：Blackwell 架构效率下限、长序列效率衰减。

残差分布（全部 19 条拟合锚点）：**13 条在 ±15% 内，平均 13.9%**，最差 46%
（0.9MP/15s 单格，原矩阵该点自身与邻格不单调，疑为测量噪声）。

## 4. 误差来源与公信力策略

1. 社区基准的硬件/软件/工作流口径不一致（最大偏差源）；
2. 低显存 + 量化 + LoRA 有每步重打补丁开销（aptech 文档明确，最大可达 +5s/步）；
3. 15s 高分辨率下二次项主导，系数外推误差增大；
4. 显存峰值受 DynamicVRAM 封顶影响，与 token 弱相关。

对策：区间展示 + 锚点透明 + 用户自校准（输入一次自己的 s/it 即可本地修正）+ 投稿回填。

## 5. 如何新增一条基准

### 5.1 新增显卡（10 分钟）

在 `data/gpus.json` 追加一条即可上线（估算器会自动用 `k_bw × 显存带宽` 兜底）：

```json
{
  "id": "rtx-5060ti-16g", "name": "RTX 5060 Ti 16GB", "vendor": "nvidia",
  "arch": "Blackwell", "sm": 120, "vram_gb": 16, "mem_type": "GDDR7",
  "mem_bw_gbps": 448, "pcie_gen": 5, "pcie_lanes": 8,
  "nvfp4_dit": true, "tier": "mid", "notes": "PCIe x8，卸载模式注意"
}
```

### 5.2 提高精度（把该卡升级到实测档）

有两种方式，任选：

1. **官方锚点**：在 `data/benchmarks.json` 追加 1-3 条实测（推荐至少一条 `high` 置信度），
   重跑 `python tools/calibrate.py` → `calibration.json` 的 `per_gpu` 会生成该卡的
   `eff_tops_median`，网页优先使用它而不是全局 k。
2. **用户自校准**：网页端输入该卡用户自己的 `s/it`，本地系数修正（无需改数据）。

### 5.3 校准档位（网页展示用）

| 档位 | 条件 | 预期误差 |
|---|---|---|
| A 实测校准 | ≥2 条该卡锚点 | ±15-20% |
| B 单点校准 | 1 条锚点 | ±25% |
| C 公式估算 | 仅规格，无锚点 | ±35%（仍可用于排序与可行性判断） |

跑 `python tools/validate.py` 校验引用完整性，全绿即可提交。

### 5.4 需要注意的边界

- **AMD (ROCm)**：带宽规律类似，但内核效率不同，需独立拟合一组 k（架构=ROCm 单独标记）；
- **Apple MLX**：运行时完全不同，不走 ComfyUI 公式，属于独立引擎（v1 只展示不计时）；
- **数据中心卡**（B300/GB200 等）：多卡并行不适用本公式，标注 `exclude_from_fit` 仅作参考。
